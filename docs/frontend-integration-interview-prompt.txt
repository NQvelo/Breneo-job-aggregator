You are an expert Frontend UI/UX Developer working on the "Breneo" platform (breneoapp — Vite + React SPA).
Task: Build a beautiful, mobile-first, interactive HR Mock Interview interface with a live camera feed and a comprehensive AI evaluation dashboard.

Tech Stack: React, TypeScript, Tailwind CSS, Lucide React (for icons).

Follow the SAME auth / BFF pattern as employer jobs and job applications in breneoapp.
Do NOT call the raw job-aggregator host from the browser for interview routes.

-------------------------------------------------------------------------------
AUTH — THREE LAYERS (match breneoapp; see src/api/interview/interviewApi.ts)
-------------------------------------------------------------------------------

LAYER 1 — BROWSER (React SPA)
- User is logged into Breneo; TokenManager holds the Breneo access JWT.
- Interview API calls use employerBffFetch() — NOT direct fetch to JOB_AGGREGATOR_BASE_URL.
- Browser sends ONLY:
    Authorization: Bearer <Breneo user JWT>
    Accept: application/json
- Browser NEVER sends EMPLOYER_POST_SECRET, JOB_AGGREGATOR_EMPLOYER_KEY, or X-Employer-Key.
- Browser does NOT send user_id in the body for interview (BFF injects it server-side).

LAYER 2 — BFF (same-origin; server/employer-jobs-proxy.mjs + server/interviewRoutes.mjs)
- Dev: Vite proxies /api/v1/interview/* → localhost:8787 (employer-jobs-proxy).
- Prod: production.mjs serves SPA + mounts the same BFF.
- BFF validates Breneo JWT via requireUserAuth → GET MAIN_API_BASE_URL/api/profile/.
- BFF resolves ctx.userId (Breneo user id string) from profile or JWT claims.
- BFF forwards to job-aggregator with:
    X-Employer-Key: <JOB_AGGREGATOR_EMPLOYER_KEY>   // same as employer job POST
    user_id: <ctx.userId>   // injected by BFF — NOT from browser
- Start: user_id in JSON body alongside job_position.
- Submit: user_id as query param ?user_id=...
- NEVER forward the user's Breneo JWT to the job-aggregator.

BFF env (server-only — .env, not VITE_*):
  JOB_AGGREGATOR_BASE_URL=https://breneo-job-aggregator.up.railway.app
  JOB_AGGREGATOR_EMPLOYER_KEY=<same as aggregator EMPLOYER_POST_SECRET>
  MAIN_API_BASE_URL=<Breneo API used at login — must match token issuer>

LAYER 3 — JOB AGGREGATOR (Django interview_api)
- Accepts BFF: X-Employer-Key (or X-Application-Key) + user_id in body/query.
- Also accepts direct Breneo JWT (Postman/tests): Authorization: Bearer <jwt> or Bearer dev:<id> in DEBUG.
- Stores user_id as plain text on Interview — no Django User FK.

CLIENT BASE URL (browser)
- Use getJobApplicationsApiBaseUrl() / same base as job applications BFF (NOT JOB_AGGREGATOR_BASE_URL).
- Local dev: window.location.origin (Vite proxy → BFF).
- Static hosts (dashboard.breneo.app): set VITE_EMPLOYER_JOBS_API_BASE_URL or VITE_EMPLOYER_BFF_URL.

EXISTING CLIENT MODULE (reuse — do not reinvent)
  src/api/interview/interviewApi.ts
    startInterview(jobPosition)           → POST /api/v1/interview/start/
    submitInterviewAudio(questionId, blob) → POST /api/v1/interview/submit-audio/{id}/
  Both use employerBffFetch from src/api/employer/employerBffClient.ts.

ERRORS
- 401 browser: missing/expired Breneo JWT (TokenManager refresh).
- 401 BFF: profile validation failed (JWT invalid/expired or MAIN_API_BASE_URL mismatch).
- 403 after profile OK: JOB_AGGREGATOR_EMPLOYER_KEY ≠ aggregator EMPLOYER_POST_SECRET (BFF secret rejected upstream).
- 404 submit: wrong question_id or interview owned by another user_id.

DEBUG (Network tab — ignore Vite HMR)
- `GET http://localhost:8080/` with `Accept: text/x-vite-ping` is NOT the interview API; it is Vite dev heartbeat.
- The real call is `POST /api/v1/interview/start/` (or submit-audio) on the same origin (8080), proxied to employer-jobs-proxy :8787.
- BFF validates JWT via GET MAIN_API_BASE_URL/api/profile/ — must match login host (see breneoapp .env MAIN_API_BASE_URL).
- Run `npm run dev` in breneoapp (starts Vite + employer-jobs-proxy); interview routes 502/ECONNREFUSED if only `npm run dev:vite`.
- 400: missing job_position, empty/invalid audio, file > 25 MB.
- 502: Whisper/LLM failure — show Georgian retry message.

API FLOW (BFF paths — what the React app calls)
-------------------------------------------------------------------------------

1) START SESSION
POST {BFF_ORIGIN}/api/v1/interview/start/
Authorization: Bearer <Breneo JWT>          // browser only
Content-Type: application/json
Body (browser sends):
{
  "job_position": "Python Developer"
}

BFF upstream → POST {JOB_AGGREGATOR_BASE_URL}/api/v1/interview/start/
Body (BFF adds user_id):
{
  "job_position": "Python Developer",
  "user_id": "<breneo-user-id>"
}

Response 201:
{
  "interview": { "id": "<uuid>", "job_position": "...", "created_at": "..." },
  "question": {
    "id": "<uuid>",              // SAVE — required for submit
    "interview_id": "<uuid>",
    "job_position": "...",
    "question_text": "<Georgian>"
  }
}

2) SUBMIT RECORDING
POST {BFF_ORIGIN}/api/v1/interview/submit-audio/<question_id>/
Authorization: Bearer <Breneo JWT>
Content-Type: multipart/form-data
Form field: audio_file = MediaRecorder Blob (video/webm or audio/webm, max 25 MB)

BFF upstream → POST .../submit-audio/<question_id>/?user_id=<breneo-user-id>
(same multipart body; BFF does not expose user_id to browser)

Response 200 → pass to InterviewReport:
