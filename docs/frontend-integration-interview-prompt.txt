You are an expert Frontend UI/UX Developer working on the "Breneo" platform.
Task: Build a beautiful, mobile-first, interactive HR Mock Interview interface with a live camera feed and a comprehensive AI evaluation dashboard.

Tech Stack: React, TypeScript, Tailwind CSS, Lucide React (for icons).

Integrate with the job-aggregator Django REST API under /api/v1/interview/ only.
Base URL: https://<aggregator-host>/api/v1/interview/

AUTH
- Both endpoints require: Authorization: Bearer <breneo-api JWT> (same token as other Breneo user flows).
- The backend resolves the Breneo user id from the JWT and stores it as plain text (user_id) — do NOT send a Django user reference or numeric auth_user id.
- Prefer calling the aggregator from Breneo-api server-side (BFF / Route Handlers / server actions) and forwarding Authorization: Bearer <token>. Never expose aggregator secrets in the browser.
- 401: missing/invalid Bearer token.
- 404 on submit: wrong question_id or question belongs to another user (scoped by user_id).
- 400: validation errors (missing job_position, missing/invalid audio file).
- 502: Whisper or LLM failure — show a friendly retry message in Georgian.

API FLOW (two steps — implement in this order)

1) START SESSION — generate question
POST /api/v1/interview/start/
Content-Type: application/json
Body:
{
  "job_position": "Python Developer"   // required string, max 255 chars
}

Response 201:
{
  "interview": {
    "id": "<uuid>",
    "job_position": "Python Developer",
    "created_at": "2026-07-07T16:00:00Z"
  },
  "question": {
    "id": "<uuid>",                    // SAVE THIS — required for submit
    "interview_id": "<uuid>",
    "job_position": "Python Developer",
    "question_text": "<Georgian LLM question>"
  }
}

2) SUBMIT RECORDING — transcribe + evaluate
POST /api/v1/interview/submit-audio/<question_id>/
Content-Type: multipart/form-data
Form field: audio_file (preferred) OR audio
- Upload the MediaRecorder Blob (video/webm or audio/webm).
- Max file size: 25 MB.
- Supported types: webm, mp3, mp4, wav, m4a, ogg (audio/* or video/* MIME).

Response 200 (pass directly to InterviewReport):
{
  "overall_score": 82,
  "status": "PASSED",                  // "PASSED" | "FAILED" — threshold >= 75
  "requires_retake": false,            // true when overall_score < 75
  "user_transcript": "<Georgian transcript from Whisper>",
  "metrics": {
    "technical_accuracy": {
      "score": 85,
      "label": "ტექნიკური სიზუსტე",
      "feedback": "<Georgian feedback>"
    },
    "structure_star": {
      "score": 78,
      "label": "პასუხის სტრუქტურა (STAR)",
      "feedback": "<Georgian feedback>"
    },
    "delivery_confidence": {
      "score": 80,
      "label": "თვითპრეზენტაცია და ენა",
      "feedback": "<Georgian feedback>"
    }
  },
  "strengths": ["..."],
  "improvements": ["..."],
  "missing_concepts": ["..."],
  "recommended_answer": "<Georgian ideal answer>"
}

TYPESCRIPT TYPES (snake_case — match JSON exactly)
- StartInterviewRequest: { job_position: string }
- StartInterviewResponse: { interview: Interview; question: InterviewQuestion }
- Interview: { id: string; job_position: string; created_at: string }
- InterviewQuestion: { id: string; interview_id: string; job_position: string; question_text: string }
- InterviewEvaluation: response shape above (all fields required except missing_concepts may be [])

SUGGESTED CLIENT MODULE
- lib/interviewApi.ts (or server actions):
  - startInterview(jobPosition: string, token: string): Promise<StartInterviewResponse>
  - submitInterviewAudio(questionId: string, blob: Blob, token: string): Promise<InterviewEvaluation>
- Build FormData: formData.append("audio_file", blob, "answer.webm")

ARCHITECTURE — two main components

1. InterviewContainer.tsx (recorder + API orchestration)
- Props: jobPosition: string (from parent route or a text input before start), authToken or a server action wrapper.
- On mount / "Start Mock Interview":
  1. Call POST /start/ with { job_position }.
  2. Store question.id and question.question_text in state.
  3. Display the Georgian question_text prominently above the video widget.
- Implement browser hardware handling using navigator.mediaDevices.getUserMedia({ video: true, audio: true }).
- Render a live HTML <video> stream (muted, playsInline, autoPlay) centered on screen — rounded corners, subtle shadow, professional interview widget look.
- Use MediaRecorder on the stream; on stop, produce a Blob (prefer video/webm; fallback audio/webm).
- UI states:
  - setup: Text input for job_position (if not passed via props) + "Start Mock Interview" + camera/mic permission reminder in Georgian.
  - idle: Question displayed + "Start Recording" (after permissions granted).
  - recording: Flashing red "REC", 2-minute countdown (auto-stop at 0), CSS audio wave visualizer, "Stop & Submit".
  - submitting: Disable controls; spinner/skeleton + "AI-ის მიერ პასუხის გაანალიზება...".
  - results: Render <InterviewReport evaluation={...} onRetake={...} />.
- On "Stop & Submit": POST multipart to /submit-audio/{question.id}/ with the Blob; transition to results on 200.
- If requires_retake is true, show a prominent "თავიდან ცდა" button that calls POST /start/ again (new question) or re-records for the same question if product allows only one attempt per question — default: start a new session via /start/.
- Handle permission denied (NotAllowedError), no devices (NotFoundError), and 502/400 API errors with clear Georgian messages.

2. InterviewReport.tsx (evaluation dashboard)
Props: evaluation: InterviewEvaluation, onRetake?: () => void

- Header Summary: SVG/Tailwind circular progress for overall_score (0–100). Green when status === "PASSED", amber/red when "FAILED". Show status badge and requires_retake callout when true.
- Metrics Breakdown: Map metrics.technical_accuracy, metrics.structure_star, metrics.delivery_confidence — horizontal bars with metric.label and score/100. Accordion or expandable row for metric.feedback on click/hover.
- Strengths vs Improvements: grid grid-cols-1 md:grid-cols-2
  - Left: strengths — soft green, checkmarks (✓).
  - Right: improvements + missing_concepts — soft orange/red, warning bullets. Label missing_concepts separately if non-empty.
- Transcript Accordion: collapsible user_transcript.
- HR Recommended Answer: blockquote/card with subtle gradient, title "HR-ის რეკომენდაცია", body recommended_answer.

UX / RESPONSIVE
- Mobile-first; video container max-width on desktop (e.g. max-w-lg mx-auto).
- Smooth CSS transitions between states.
- Stop MediaStream tracks on unmount and after submit.
- Do not block UI on camera preview while waiting for /start/ — show loading on question fetch only.

EXAMPLE PAGE FLOW
1) User enters target role (job_position) → Start Mock Interview.
2) API returns Georgian question → user reads question → Start Recording.
3) User answers in Georgian (spoken) → Stop & Submit.
4) Show InterviewReport with evaluation JSON.
5) If requires_retake, offer retry (new /start/ recommended).

Use snake_case in types and API payloads. Keep fetch/axios with Bearer token in server actions or BFF routes when possible; if calling from client, use the user's session token only — never employer or application secrets.
