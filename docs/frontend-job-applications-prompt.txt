FRONTEND INTEGRATION — JOB APPLICATIONS (copy this into Cursor for the UI repo)
================================================================================

Backend is verified working via Postman. Implement the UI using the rules below.

-------------------------------------------------------------------------------
SUMMARY
-------------------------------------------------------------------------------

• Job aggregator base URL for public job data: NEXT_PUBLIC_JOB_AGGREGATOR_URL
• Apply / my applications / withdraw: browser → YOUR Next.js API routes (BFF) only
• BFF → job-aggregator with header X-Application-Key = server env EMPLOYER_POST_SECRET
• BFF sends external_user_id = logged-in Breneo user id (string)
• Do NOT use Authorization: Bearer on job-aggregator
• Do NOT put EMPLOYER_POST_SECRET in NEXT_PUBLIC_* or client code

AGGREGATOR ENDPOINTS (called from BFF, not browser)
-------------------------------------------------------------------------------

Base: process.env.JOB_AGGREGATOR_BASE_URL

Auth on apply / list / withdraw:
  Header: X-Application-Key: process.env.EMPLOYER_POST_SECRET
  User:   external_user_id in query or JSON body (= session user id)

Recruiter applicants (optional BFF):
  Header: X-Employer-Key: process.env.EMPLOYER_POST_SECRET  (same secret, different header name)

--- Public (browser may call directly) ---

  GET  /api/v1/jobs/?page=1&limit=20
  GET  /api/v1/jobs/{id}/
  GET  /api/search?...
  GET  /api/job-details?...

--- BFF only (user session required) ---

  POST   /api/jobs/{jobId}/apply
         Body: { "external_user_id": "<userId>" }

  GET    /api/users/me/applications?external_user_id=<userId>&page=1&limit=20&sort=-applied_at

  DELETE /api/jobs/{jobId}/application?external_user_id=<userId>

--- BFF only (recruiter / employer dashboard) ---

  GET    /api/jobs/{jobId}/applicants?page=1&limit=20&sort=-applied_at

-------------------------------------------------------------------------------
TYPESCRIPT
-------------------------------------------------------------------------------

type ApplicationStatus = "applied" | "reviewed" | "rejected" | "accepted";

interface ApiEnvelope<T> {
  success: boolean;
  message: string;
  data: T | null;
  error?: string;
}

interface JobSummary {
  id: number;
  title: string;
  company_name: string;
  company_logo: string | null;
  location: string | null;
  workplace_type: string | null;
  platform: string;
  supports_in_app_apply: boolean;
  apply_url: string | null;
  is_active: boolean;
}

interface JobApplication {
  id: number;
  user_id: string;
  job_id: number;
  status: ApplicationStatus;
  applied_at: string;
  is_withdrawn: boolean;
  withdrawn_at: string | null;
  job: JobSummary;
}

interface PaginatedApplications {
  items: JobApplication[];
  pagination: {
    page: number;
    limit: number;
    total_pages: number;
    total_items: number;
    has_next: boolean;
    has_previous: boolean;
  };
}

-------------------------------------------------------------------------------
NEXT.JS BFF ROUTES (App Router) — implement these four routes
-------------------------------------------------------------------------------

Shared helper (lib/job-aggregator-bff.ts):

  const AGGREGATOR = process.env.JOB_AGGREGATOR_BASE_URL!;
  const APP_KEY = process.env.EMPLOYER_POST_SECRET!;

  export async function aggregatorFetch(path: string, init?: RequestInit) {
    return fetch(`${AGGREGATOR}${path}`, {
      ...init,
      headers: {
        ...(init?.headers ?? {}),
        "X-Application-Key": APP_KEY,
      },
    });
  }

--- app/api/app/jobs/[jobId]/apply/route.ts ---

  POST → aggregator POST /api/jobs/{jobId}/apply
  body to aggregator: { external_user_id: sessionUserId }

--- app/api/app/users/me/applications/route.ts ---

  GET → aggregator GET /api/users/me/applications?external_user_id=...&page=&limit=20&sort=-applied_at
  forward query param page from request

--- app/api/app/jobs/[jobId]/application/route.ts ---

  DELETE → aggregator DELETE /api/jobs/{jobId}/application?external_user_id=...

--- app/api/app/jobs/[jobId]/applicants/route.ts (employer dashboard) ---

  GET → aggregator GET /api/jobs/{jobId}/applicants?...
  use header X-Employer-Key instead of X-Application-Key (same secret value)

Session: implement getSessionUserId() from your existing Breneo login (cookie / session).
Return 401 from BFF if no user id before calling aggregator.

BROWSER CLIENT (only calls /api/app/* on your domain)

const applyToJob = async (jobId: number) => {
  const res = await fetch(`/api/app/jobs/${jobId}/apply`, { method: "POST" });
  const json: ApiEnvelope<JobApplication> = await res.json();
  if (!json.success) {
    if (json.error === "already_applied") return { alreadyApplied: true };
    throw new Error(json.message);
  }
  return { data: json.data };
};

const getMyApplications = async (page = 1) => {
  const res = await fetch(`/api/app/users/me/applications?page=${page}`);
  const json: ApiEnvelope<PaginatedApplications> = await res.json();
  if (!json.success) throw new Error(json.message);
  return json.data!;
};

const withdrawApplication = async (jobId: number) => {
  const res = await fetch(`/api/app/jobs/${jobId}/application`, { method: "DELETE" });
  const json: ApiEnvelope<JobApplication> = await res.json();
  if (!json.success) throw new Error(json.message);
  return json.data;
};

-------------------------------------------------------------------------------
REACT / UI FLOWS
-------------------------------------------------------------------------------

Job detail page:
  1. GET {NEXT_PUBLIC_JOB_AGGREGATOR_URL}/api/v1/jobs/{id}/  (public)
  2. If user logged in && job.supports_in_app_apply:
       GET /api/app/users/me/applications?page=1 (BFF)
       show "Applied" if items.some(a => a.job_id === job.id && !a.is_withdrawn)
  3. Apply button:
       - supports_in_app_apply → POST /api/app/jobs/{id}/apply
       - else → existing apply_url link only

"My applications" page:
  - GET /api/app/users/me/applications?page=N
  - Render data.items[].job (title, company_name, logo, location)
  - Show data.items[].status, data.items[].applied_at
  - Withdraw → DELETE /api/app/jobs/{job_id}/application → refresh list

Employer job applicants page:
  - GET /api/app/jobs/{jobId}/applicants
  - Table from data.items (user_id, status, applied_at, user object if present)

Loading / errors:
  - Disable Apply while POST in flight
  - Toast json.message on success: false
  - 409 / already_applied → show "Already applied" (not a crash)

-------------------------------------------------------------------------------
HTTP STATUS CODES (from aggregator via BFF)
-------------------------------------------------------------------------------

  201  apply created
  200  list / withdraw OK
  401  missing session (BFF) or bad X-Application-Key (misconfigured server)
  400  employer_job_only — wrong job type (UI should not offer in-app apply)
  404  job or application not found
  409  already_applied
