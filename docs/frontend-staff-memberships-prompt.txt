FRONTEND UPDATE — COMPANY STAFF MEMBERSHIPS (PROFILE + ADMIN)
=============================================================

Scope: employer dashboard only. Implement company team / staff members UI and BFF
routes for staff-memberships. Do NOT change job seeker flows or public job board.

You already call /api/employer/ via BFF with X-Employer-Key. This prompt adds:
  • stored email, first name, surname per staff member
  • is_admin flag + admin-only remove / promote rules
  • auto-admin for the first member of a company

-------------------------------------------------------------------------------
AUTH & BASE URL (unchanged)
-------------------------------------------------------------------------------

• Browser → your Next.js /api/app/employer/* routes only
• BFF → job-aggregator with header: X-Employer-Key: process.env.EMPLOYER_POST_SECRET
• Base: ${JOB_AGGREGATOR_BASE_URL}/api/employer/
• Never put X-Employer-Key in client bundles

Identity: Breneo logged-in user id (string) = external_user_id in query/body.
Alias staff_user_id accepted in query params.

WHAT CHANGED ON THE BACKEND
-------------------------------------------------------------------------------

Table company_staff_membership now has:

  external_user_email
  external_user_name      (first name)
  external_user_surname   (last name)
  is_admin                (boolean)

Every staff-memberships API response includes:

  id
  company_id
  external_user_id
  external_user_email
  external_user_name
  external_user_surname
  user_id                 // same as external_user_id
  user_email              // same as external_user_email
  user_name               // same as external_user_name
  user_surname            // same as external_user_surname
  is_admin
  created_at

Use either external_user_* or user_* in TypeScript; values are identical.

-------------------------------------------------------------------------------
ENDPOINTS (staff only)
-------------------------------------------------------------------------------

GET    /api/employer/staff-memberships
       ?company_id=<integer>           // filter one company
       ?external_user_id=<id>          // filter by user (staff_user_id alias)

POST   /api/employer/staff-memberships
       Body: company_id, external_user_id, optional profile + is_admin

GET    /api/employer/staff-memberships/{membershipId}

PATCH  /api/employer/staff-memberships/{membershipId}
       ?external_user_id=<acting admin id>   // required to change is_admin

DELETE /api/employer/staff-memberships/{membershipId}
       ?external_user_id=<acting admin id>   // required for admin-gated remove

Shortcut (same rows):

POST   /api/employer/companies/{company_id}/members
       Body: external_user_id + optional profile + is_admin

DELETE /api/employer/companies/{company_id}/members?external_user_id=<target>
       &external_user_id=<acting admin>  // use query for BOTH:
         • member to remove = body or first param (see below)
         • acting admin = MUST be the logged-in user for permission check

For DELETE members shortcut:
  • Target user to remove: ?external_user_id= on query OR body external_user_id
  • Acting admin: append ?external_user_id=<loggedInUserId> on the BFF→aggregator call
    (same query key — aggregator reads requester from query; target from body/query)

Prefer staff-memberships DELETE with membership id for clarity:

  DELETE /api/employer/staff-memberships/{id}?external_user_id={loggedInUserId}

Company JSON still has read-only staff_user_ids: string[] — list UI should use
GET staff-memberships?company_id= for full rows (name, email, is_admin).

-------------------------------------------------------------------------------
ADMIN RULES (implement in UI + BFF)
-------------------------------------------------------------------------------

ON CREATE
  • First staff row for a company → backend forces is_admin: true (ignore false).
  • Later members → is_admin defaults false unless you send true AND an admin creates them.
  • On onboarding (user joins empty company), show Admin checked and disabled.

ON DELETE (when BFF sends ?external_user_id= logged-in user)
  • Only is_admin members can remove OTHERS.
  • Cannot remove yourself → show error, ask to transfer admin first.
  • Cannot remove the only admin.
  • 403 body: { "error": "<message>" }

ON PATCH is_admin (when BFF sends ?external_user_id= logged-in admin)
  • Only admins can toggle another member's is_admin.
  • Cannot demote the last admin.
  • 400 validation error if not allowed.

If DELETE/PATCH omit ?external_user_id=, server trusts X-Employer-Key only (BFF).
For user-facing team management, ALWAYS send ?external_user_id=<session user id>.

FIX 1 — TYPESCRIPT TYPES
-------------------------------------------------------------------------------

  interface CompanyStaffMembership {
    id: number;
    company_id: number;
    external_user_id: string;
    external_user_email: string;
    external_user_name: string;
    external_user_surname: string;
    user_id: string;
    user_email: string;
    user_name: string;
    user_surname: string;
    is_admin: boolean;
    created_at: string;
  }

  function staffDisplayName(m: CompanyStaffMembership): string {
    const name = m.external_user_name || m.user_name || "";
    const surname = m.external_user_surname || m.user_surname || "";
    return [name, surname].filter(Boolean).join(" ") || m.external_user_id;
  }

  function staffEmail(m: CompanyStaffMembership): string {
    return m.external_user_email || m.user_email || "";
  }

  function isCurrentUserAdmin(
    memberships: CompanyStaffMembership[],
    userId: string
  ): boolean {
    return memberships.some(
      (m) => m.external_user_id === userId && m.is_admin
    );
  }

FIX 4 — BFF: REMOVE MEMBER (admin only)
-------------------------------------------------------------------------------

  export async function DELETE(
    req: Request,
    { params }: { params: { companyId: string; membershipId: string } }
  ) {
    const user = await getSessionUser();
    if (!user?.id) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });

    const url = new URL(
      `${process.env.JOB_AGGREGATOR_BASE_URL}/api/employer/staff-memberships/${params.membershipId}`
    );
    url.searchParams.set("external_user_id", String(user.id));

    const res = await fetch(url.toString(), {
      method: "DELETE",
      headers: { "X-Employer-Key": process.env.EMPLOYER_POST_SECRET! },
    });

    if (res.status === 403) {
      const body = await res.json();
      return NextResponse.json(
        { error: body.error ?? "Not allowed" },
        { status: 403 }
      );
    }
    if (res.status === 204) return new NextResponse(null, { status: 204 });
    return NextResponse.json(await res.json(), { status: res.status });
  }

Map 403 messages for toast:
  • "Only company admins can remove staff members."
  • "Admins cannot remove themselves. Transfer admin to another member first."
  • "Cannot remove the only admin for this company."
