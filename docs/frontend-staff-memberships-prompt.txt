WHAT CHANGED ON THE BACKEND
-------------------------------------------------------------------------------

Table company_staff_membership now has:

  external_user_email
  external_user_name      (first name)
  external_user_surname   (last name)
  status                  (string enum — see below)

status values (exact strings):

  "pending"   — invited / awaiting approval; NO full company access yet
  "member"    — regular staff
  "admin"     — can manage team (remove others, change status)

Every staff-memberships API response includes:

  id
  company_id
  external_user_id
  external_user_email
  external_user_name
  external_user_surname
  user_id                 // same as external_user_id
  user_email              // same as external_user_email
  user_name               // same as external_user_name
  user_surname            // same as external_user_surname
  status                  // "pending" | "member" | "admin"
  created_at

There is NO is_admin field. Use status === "admin" instead.

-------------------------------------------------------------------------------
STATUS RULES (implement in UI + BFF)
-------------------------------------------------------------------------------

ON CREATE
  • First staff row for a company → backend forces status: "admin" (ignores other values).
  • Later members → default status "member" unless you send "pending" or "admin".
  • Invite flow: POST with status: "pending" for users awaiting approval.

ON ACCESS
  • pending users cannot open company detail/jobs via scoped ?external_user_id= (404).
  • member and admin have full employer access for that company.

ON DELETE (BFF sends ?external_user_id= logged-in user)
  • Only status === "admin" can remove others.
  • Cannot remove yourself.
  • Cannot remove the only admin.
  • 403: { "error": "<message>" }

ON PATCH status (BFF sends ?external_user_id= logged-in admin)
  • Only admins can change another member's status.
  • Cannot demote the last admin (admin → member/pending).
  • 400 validation error if not allowed.

For user-facing team management, ALWAYS send ?external_user_id=<session user id>.

FIX 1 — TYPESCRIPT TYPES
-------------------------------------------------------------------------------

  type StaffMembershipStatus = "pending" | "member" | "admin";

  interface CompanyStaffMembership {
    id: number;
    company_id: number;
    external_user_id: string;
    external_user_email: string;
    external_user_name: string;
    external_user_surname: string;
    user_id: string;
    user_email: string;
    user_name: string;
    user_surname: string;
    status: StaffMembershipStatus;
    created_at: string;
  }

  function staffDisplayName(m: CompanyStaffMembership): string {
    const name = m.external_user_name || m.user_name || "";
    const surname = m.external_user_surname || m.user_surname || "";
    return [name, surname].filter(Boolean).join(" ") || m.external_user_id;
  }

  function staffEmail(m: CompanyStaffMembership): string {
    return m.external_user_email || m.user_email || "";
  }

  function isCurrentUserAdmin(
    memberships: CompanyStaffMembership[],
    userId: string
  ): boolean {
    return memberships.some(
      (m) => m.external_user_id === userId && m.status === "admin"
    );
  }

  function statusLabel(status: StaffMembershipStatus): string {
    switch (status) {
      case "admin": return "Admin";
      case "pending": return "Pending";
      default: return "Member";
    }
  }
